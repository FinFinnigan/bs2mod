# C01.04 — Pre-commit verification for full-tree commit

## Routing
Routing: run mandatory agent-aware preflight before execution.
Run mandatory `ROUTING-PREFLIGHT.md` immediately before execution.
Do not hardcode a named agent here.
Capability preference: verification/security (scope, secrets, exclusions inspection).

## Mode
READ ONLY. No `git add`, no commit. This is the verification gate that must pass before C01.05 may request CEO approval to commit.

## Outcome
A complete, evidence-backed pre-commit verification report for committing the remaining untracked `BS2Mod-site/` tree (plus any evidence-doc edits from C01.01–C01.03 still uncommitted): intended scope listed, secrets scan clean, exclusions confirmed, regression green.

## Scope (inspect only)
1. **Intended commit scope** — live `git status --short -- .` from project root. Expected shape (re-verify count): 15 untracked paths (`src/`, `.env.example`, `.eslintrc.json`, `.gitignore`, `drizzle.config.ts`, `netlify.toml`, `next.config.mjs`, `open-next.config.ts`, `package.json`, `package-lock.json`, `scripts/`, `tsconfig.json`, `vitest.config.ts`, `wrangler.jsonc`, `BOYSHOP-NEW-WORKFLOW-PACK/`) plus modified `docs/evidence/*.md` if C01.01–C01.03 landed and were not yet committed.
2. **Explicit exclusions** — confirm still excluded/untracked-out: `node_modules/`, `.next/`, `.open-next/`, `.wrangler/`, `.env`, `.env.local`, `.env*.local`, `.dev.vars`, `.dev.vars.*`, `.omo/`, `opencode.json` (repo-level), `tsconfig.tsbuildinfo`, `BOYSHOP-NEW-WORKFLOW-PACK/BoyShop-Agent-Aware-Pack.zip` (binary — decide include/exclude explicitly; C00.12 precedent: exclude the zip). Use `git check-ignore -v` for ignore rules; probe with temp files if needed then delete probes.
3. **Secrets scan** — scan intended-scope files for real credentials (Mollie `live_*`/`test_` keys beyond `.env.example` placeholders, Neon URLs, API tokens, passwords). `.env.example` placeholders and public test fixture `test_abc` in tests are not secrets. Never echo actual secret values if any are found — report file + line only.
4. **Evidence-doc consistency** — after C01.01–C01.03, the five evidence docs should no longer claim "no commit exists"; spot-check headers.
5. **Regression gates** (from project root, mock/no-env):
   - `npm run typecheck` → 0 errors
   - `npm run lint` → exit 0 (2 pre-existing warnings acceptable)
   - `npm run test` → all green (expect 292/292 unless tests changed — re-run, do not trust expectation)
   - `npm run build` → success
6. **Version** — `package.json` == `package-lock.json` == `0.11.1`.

## Out of scope
- Any git staging or commit (C01.05 owns that, and only after CEO approval).
- Fixing anything the verification finds beyond reporting it (if a secret is found, STOP and surface it — do not silently "fix" by committing around it).
- Phase 21 broad release audit.

## Implementation
None — read-only verification producing a report in the completion response.

## Verification
The completion response itself must contain: exact scope list, exclusion evidence (`git check-ignore` results), secrets-scan verdict, regression command results (actual numbers), and an explicit GO / NO-GO for C01.05.


## Permanent execution rules

- Execute exactly **one tiny chunk** per run.
- One chunk = one concern, one small directly related file group, one independently verifiable behavior.
- Before every chunk launches, run the mandatory **agent + model routing preflight** from `ROUTING-PREFLIGHT.md`.
- Consider **all currently installed OMO agents** before choosing the executor. Never assume the installed-agent set is unchanged.
- Agent choice and model choice are separate decisions.
- Never silently switch model/provider or broaden scope because a stronger agent/model exists.
- `NEXT.md` is the only current execution entry.
- Repository truth beats stale documentation.
- `MASTER-SPEC.md` is stable product truth.
- `CURRENT-STATE.md` is concise live repo truth.
- `IMPLEMENTATION-MAP.md` is the dynamic route map.
- Future implementation chunks are generated from repository evidence, not guessed in advance.
- Preserve the modular/no-code landing-to-checkout architecture.
- Preserve the current BoyShop design as the first reusable template.
- No test deletion or test weakening merely to get green.
- No broad release audit unless the active chunk specifically authorizes it.
- No live DB migration without CEO authorization.
- No `MOLLIE_ALLOW_LIVE=true` without CEO authorization.
- Never commit secrets.
- Never use `git add -A`.
- No `as any`, `@ts-ignore`, `@ts-expect-error`, or empty catch blocks.
- No new npm dependencies unless explicitly authorized by the active chunk.
- Never silently include unrelated visual work.
- Git add/commit/tag/push require explicit user approval unless already authorized for that exact scope.
- Implementation/verification happen first; project-documentation sync happens once at closeout where applicable.
- If unrelated issues appear, report `OUT OF SCOPE — NOT CHANGED`.
- Re-evaluate the remaining plan after every chunk; skip, split, insert, or reorder future chunks when repo evidence warrants it.
- Rewrite `NEXT.md` to exactly one next chunk, then STOP.
