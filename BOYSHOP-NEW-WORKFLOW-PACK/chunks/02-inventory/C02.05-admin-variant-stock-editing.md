# C02.05 — Admin variant-stock editing

## Routing
Routing: run mandatory agent-aware preflight before execution.
Run mandatory `ROUTING-PREFLIGHT.md` immediately before execution.

Capability preference: implementation (admin form + server-action plumbing).

## Outcome
The admin product edit form exposes **per-variant quantity (stock) inputs**, `productFields` reads them, and saving updates `variants.stock` through the already-capable backend mutation path. Edited values persist to the variant and, through the C02.04 availability rule, flow into availability reads without toggling the product-level flag.

## Scope
- `src/app/admin/(protected)/products/product-form.tsx` — add per-variant stock (quantity) inputs in edit mode next to the existing variant data (~lines 208–216 currently render only the product-level `inStock` checkbox); if C02.04 made that checkbox derived, render it read-only/labeled as derived — no layout redesign.
- `src/app/admin/(protected)/products/actions.ts` — `productFields()` (~line 82) must read and parse the variant stock inputs (non-negative integers) and pass them through the existing `adminProductSchema` (`src/lib/backend/api/validation.ts:46` — already rejects negative and fractional variant stock per `src/lib/backend/api/__tests__/validation.test.ts:125–156`).
- The admin products API (`src/app/api/admin/products/route.ts` ~line 50 and the update route plus the service/repo mutation path, `updateAdminProduct` in `src/lib/backend/repositories/drizzle/catalog.ts` ~lines 394–401) — touch **only** if execution proves a pass-through gap; recon indicates the mutation path and validation already handle variant stock.
- No changes to `adminProductSchema` unless a genuine bug is proven — report instead of changing.

## Out of scope

- Availability derivation (C02.04), checkout atomicity (C02.01), DB constraints (C02.03), DB-backed tests (C02.02).
