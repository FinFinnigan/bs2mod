# C02.04 — One authoritative availability rule

## Routing
Routing: run mandatory agent-aware preflight before execution.
Run mandatory `ROUTING-PREFLIGHT.md` immediately before execution.
Do not hardcode a named agent here.
Capability preference: implementation (availability derivation reconciliation).

## Outcome
Variant quantities (`variants.stock`) are the **single source of truth** for availability. Every availability read — storefront card, cart card, admin record — and every write that touches stock uses one shared derivation, so product-level `inStock` can no longer disagree with variant stock.

## Scope
- One tiny shared helper in a single backend module (new file, smallest home chosen by executor, e.g. `src/lib/backend/availability.ts`): exported `isInStock(variants: ReadonlyArray<{ stock: number }>): boolean` → true iff at least one variant has `stock > 0` (confirm product↔variant cardinality at execution — master/first-variant treatment must match the actual data model).
- Reads to update so they derive `inStock` from variant stock instead of trusting the stored boolean:
  - `rowToCard()` `src/lib/backend/repositories/drizzle/catalog.ts:32`
  - `rowToAdminProduct()` `src/lib/backend/repositories/drizzle/catalog.ts:91`
  - `variantToProductCard()` `src/lib/backend/repositories/drizzle/cart.ts:15`
  - `toAdminProduct()` `src/lib/backend/repositories/memory/index.ts:77`
- Writes to sync: `createAdminProduct` / `updateAdminProduct` in both the Drizzle catalog repo and the memory repo — whenever variant stock changes, set `products.inStock` from the same helper so the stored column stops disagreeing (the column is retained; removing it is out of scope).
- Checkout revalidation and cart limit code: read the same rule (confirm at execution whether they read the boolean — if so, switch them to the helper).
- Small unit tests for the helper and for each consumer with disagreeing fixtures (stored false + positive variant stock → reads show available; stored true + all-zero variants → unavailable).

## Out of scope
- Removing/deprecating the `products.inStock` column (schema change → separate migration chunk).
- Checkout atomicity (C02.01), DB-backed tests (C02.02), DB constraints (C02.03), admin variant-stock UI (C02.05).
- Any product data migration/backfill of existing rows.

## Implementation
Smallest safe change: add the helper, route every listed reader through it, and make the listed writers compute the stored column from it. No schema changes, no behavior change outside availability reads/writes, no new dependencies.

## Verification
- Unit tests: the helper returns the correct boolean; each consumer maps disagreeing fixtures to the derived rule through both the Drizzle and memory repos.
- `npm run typecheck`; `npm test` green (no deletions or weakening); `npm run build` passes.
- `git diff --stat` limited to the named helper + consumers + tests.
