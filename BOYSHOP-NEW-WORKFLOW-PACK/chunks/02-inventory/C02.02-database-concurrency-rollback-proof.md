# C02.02 — Database-backed concurrency and rollback proof

## Routing
Routing: run mandatory agent-aware preflight before execution.
Run mandatory `ROUTING-PREFLIGHT.md` immediately before execution.
Do not hardcode a named agent here.
Capability preference: test engineering against a live database.

## Outcome
Automated tests drive the **real Drizzle order repository** (not the in-memory one) against an isolated test database and prove: a mid-create failure rolls back the stock decrement; concurrent duplicate idempotency-key creates produce exactly one order and one decrement; a last-unit race never leaves stock negative; a successful create persists order + items + address + decrement together. The recon blind spot — production rollback and concurrent checkout safety are currently unproven because the suite exercises only the in-memory repository — is closed with evidence.

## Scope
- New `src/lib/backend/repositories/drizzle/__tests__/order.test.ts` (Vitest; runner confirmed `npm test` = `vitest run`) plus at most one small test helper; no other test files touched.
- Test database wiring: database URL read from the environment, never committed (`.dev.vars`/`.env` are git-ignored; never write secrets into the repo).
- Per C01.08, live `boyshop/main` must **not** receive test writes: use an isolated database (local Postgres if available/configured, else a Neon test branch — snapshot + branch creation are already mandated prerequisites for any DB work).
- Production code: only the smallest fix to the C02.01 transaction path if a test exposes a defect in it (same concern family — checkout atomicity). Anything else discovered = `OUT OF SCOPE — NOT CHANGED`.

## Out of scope
- Live/production database writes and migrations (CEO-gated).
- Schema constraint work (C02.03), availability rule (C02.04), admin UI (C02.05).
- Expanding test coverage beyond order-create atomicity/concurrency (no new unrelated test files).
- New npm dependencies.

## Implementation
Smallest safe change: this chunk assumes C02.01 has landed (transactional `create()`). If it has not, STOP and point `NEXT.md` back to C02.01. Then instantiate the real Drizzle order repository against the isolated test database (mirroring `db/client.ts` wiring) and write the proof tests:
1. **Rollback** — cause a failure after the decrement step (invalid address payload or forced throw) and assert stock unchanged and zero order/item/address rows.
2. **Idempotency race** — `Promise.all` of N creates with the same key → exactly one order row and one net decrement.
3. **Last-unit race** — two concurrent creates for the final unit → one success, one stock conflict, stock never negative.
4. **Atomic success** — after a normal create, order + items + address + decremented stock are all visible.

Where an assertion relies on unique-key behavior, verify the schema's actual constraints at execution rather than assuming them. The suite must run with `npm test` when a test-URL-configured environment is present, and skip with a clear message naming the missing variable when none is — **never** point at live data. The proof must actually be executed against a real database and the evidence recorded.
