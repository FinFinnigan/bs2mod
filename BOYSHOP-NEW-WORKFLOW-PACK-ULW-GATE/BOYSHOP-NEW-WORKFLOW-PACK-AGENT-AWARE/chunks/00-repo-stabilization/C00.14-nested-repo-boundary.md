# C00.14 — Nested-repo boundary decision

## Execution mode

ULW: NOT REQUIRED

## Routing
Run mandatory `ROUTING-PREFLIGHT.md` immediately before execution.
Do not hardcode a named agent here.

## Outcome
READ ONLY + user decision. Decide the ownership boundary between the standalone `BS2Mod-site` repository and the enclosing `C:\dev` repository that still tracks its files. Do not decide for the user. No parent-repo index change, no commit.

## Scope
The Git-suitability hazard found by C00.10: `C:\dev` (origin `FinFinnigan/dev.git`) is a separate Git repository (50 commits) whose index still tracks 481 `BS2Mod-site/**` files — embedded, not a submodule (index modes `100644`, no `160000` gitlink). The `C:\dev\.gitignore` lines 1–3 already declare that `BS2Mod-site` lives in its own repository and list `BS2Mod-site/`, but the ignore is ineffective because the paths are already tracked. `BS2Mod-site` itself is healthy and standalone (root `C:/dev/BS2Mod-site`, HEAD `9286a8d`, `origin FinFinnigan/bs2mod.git`, in sync).

## Out of scope
No editing of `BS2Mod-site` source, config, package, deployment, evidence, or secret files. No `git rm --cached`, no commit, no history rewrite, no push in either repository. Not the C00.11 MODALITY_WORKBOOK/opencode.json ownership question and not the C00.12/C00.13 verification/commit work.

## Implementation
None — this chunk only presents the decision and its options; it changes nothing.

Decision to put to the user:
1. Remove `BS2Mod-site` from the `C:\dev` index only (`git rm -r --cached BS2Mod-site` in `C:\dev`, leaving the working files and the nested repo untouched), so the existing `C:\dev\.gitignore` rule takes effect and the content is owned by one repository only; or
2. Leave `C:\dev` as-is and accept that one tree is committed in two repositories, with the standing risk that an add/commit in `C:\dev` commits `BS2Mod-site` edits into `FinFinnigan/dev`.

Both options require the owner's explicit approval because they act on a different repository; any chosen remediation becomes its own tiny, approved follow-up chunk.

## Verification
- `git -C C:\dev ls-files -s BS2Mod-site | Select-Object -First 3` → modes `100644` (tracked files, not a gitlink).
- `git -C C:\dev ls-files BS2Mod-site/.gitignore` → tracked; `git -C C:\dev check-ignore -v BS2Mod-site` → no output (tracked paths cannot be ignored).
- `git -C C:\dev status --porcelain -- BS2Mod-site/.gitignore` → ` M BS2Mod-site/.gitignore`.
- `git -C C:\dev remote -v` → `origin https://github.com/FinFinnigan/dev.git`.
- `git -C C:\dev\BS2Mod-site rev-parse --show-toplevel` → `C:/dev/BS2Mod-site`; `git -C C:\dev\BS2Mod-site remote -v` → `origin https://github.com/FinFinnigan/bs2mod.git`.
